# 💳 Bank Cards — система управления банковскими картами

Backend-сервис на **Java 17 + Spring Boot** для управления банковскими картами, пользователями и внутренними переводами между картами.

Проект демонстрирует разработку REST API, работу с PostgreSQL, Spring Security, JWT-аутентификацией, ролевой моделью доступа, транзакциями, миграциями БД и контейнеризацией через Docker.

---

## 🔹 Основные функции

### 👑 Администратор

- Создание банковских карт для пользователей.
- Просмотр всех карт с фильтрацией по владельцу и статусу.
- Блокировка, активация и удаление карт.
- Просмотр пользователей.
- Удаление пользователей с бизнес-ограничениями:
  - администратора нельзя удалить;
  - пользователя с положительным балансом нельзя удалить.

### 👤 Пользователь

- Просмотр своих карт с пагинацией и фильтрацией.
- Просмотр баланса карты.
- Запрос блокировки собственной карты.
- Перевод средств между своими картами.

### 🔐 Безопасность

- JWT-аутентификация.
- Access и Refresh токены.
- Ролевая модель доступа: `ROLE_ADMIN`, `ROLE_USER`.
- Хранение номеров карт в зашифрованном виде.
- Маскирование номеров карт при выдаче через API.
- Проверка принадлежности карты пользователю.
- Защита переводов от race condition с помощью пессимистической блокировки.

## 🔹 Архитектура

Приложение построено как монолитный backend-сервис со слоистой архитектурой.

```text
Client / Swagger UI
        ↓
REST Controllers
        ↓
Service Layer
        ↓
Repositories
        ↓
PostgreSQL
```
---

## 🔹 Основные слои проекта:

- **controller** — REST-контроллеры для auth, admin и user API.
- **service** — бизнес-логика пользователей, карт, переводов и токенов.
- **repository** — работа с базой данных через Spring Data JPA.
- **entity** — JPA-сущности.
- **dto** — request/response-модели API.
- **mapper** — преобразование сущностей в DTO.
- **security** — JWT-фильтры, авторизация и настройка Spring Security.
- **exception** — кастомные исключения и глобальный обработчик ошибок.
- **util** — генерация, шифрование и маскирование номеров карт.
- **db/migration** — Liquibase-миграции

## 🔹 Ключевые инженерные решения
- Разделение API на пользовательскую и административную зоны
- Настройка доступа к endpoint'ам через роли ```ADMIN``` и ```USER```
- Использование Access Token и Refresh Token для аутентификации
- Хранение Refresh Token в базе данных
- Маскирование номеров карт в API-ответах
- Хранение номеров карт не в открытом виде
- Использование ```@Transactional``` для операций с финансами
- Использование пессимистической блокировки при переводах между картами
- Управление схемой БД через Liquibase
- Документирование API через Swagger/OpenAPI
- Подготовка Docker Compose для быстрого локального запуска

## 🔹 Безопасность и ограничения учебной реализации
### Проект является учебным/pet-проектом и демонстрирует основные подходы к защите backend-сервиса:

- JWT-аутентификация;
- ролевая модель;
- разграничение доступа;
- маскирование чувствительных данных;
- хранение номеров карт в зашифрованном виде;
- транзакционная обработка переводов.

### В текущей реализации для шифрования используется:
```text
AES/ECB/PKCS5Padding
```

Для production-сценариев предпочтительнее использовать более безопасный подход, например AES-GCM с IV/nonce и корректным управлением ключами.
